# Barber MAX Bot

Лёгкий бот для мессенджера **MAX** — приём записей на услуги парикмахера с хранением данных в Google Sheets, учётом таймзоны салона и автоматическими напоминаниями.

Проект написан на Node.js с использованием `@maxhub/max-bot-api` и Google Sheets API.

**Связанная документация**

- [MASTER.md](MASTER.md) — пошаговая инструкция для мастера салона (работа в боте и Google Sheets)
- [MANAGER.md](MANAGER.md) — настройка сервера, `.env`, Google API, справочник менеджера

## Ключевые возможности

- Пошаговая запись через `ctx.session` (услуга → дата → время → контакт → подтверждение).
- **Управление услугами**: добавление, редактирование, удаление услуг с ценами и продолжительностью (через админ-меню).
- **Управление расписанием**: настройка рабочих дней и часов мастера (по датам и по дням недели) через админ-меню, без ручного редактирования таблицы.
- Управление слотами: учитываются блокировки из листа **«Блокировка времени»** и уже подтверждённые записи.
- Автоматическое создание листов и заголовков в Google Sheets при старте.
- Портфолио и премиальная визитка: после `/start` бот показывает до 6 лучших работ (HTTPS-ссылки из настроек, загрузка через MAX API).
- Кнопка «Как добраться»: в главном меню клиенту отправляется ссылка на Яндекс.Карты (из Google Sheets).
- Напоминания: за день записи (08:00 по таймзоне салона), за 2 часа до записи, клиентам без визита более 28 дней.
- Хранение клиентов и статистики в листе `Клиенты`.
- Менеджерские уведомления (опционально, через `MANAGER_CHAT_ID` — user_id менеджера в MAX).

## Требования

- Node.js 18+ (рекомендуется).
- Аккаунт сервисного аккаунта Google с доступом редактирования к таблице.
- Токен бота MAX ([платформа MAX для партнёров](https://business.max.ru)).

## Быстрый старт

1. Склонируйте репозиторий и перейдите в каталог проекта.
2. Создайте файл `.env` в корне проекта:

```
MAX_BOT_TOKEN=ваш_токен_бота_MAX
GOOGLE_SHEETS_ID=ID_вашей_таблицы
GOOGLE_CLIENT_EMAIL=service-account@project.iam.gserviceaccount.com
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
DEFAULT_TIMEZONE=Asia/Yekaterinburg
MANAGER_CHAT_ID=1234567890
```

Подробная настройка Google Sheets, Calendar и MAX — в [MANAGER.md](MANAGER.md).

3. Убедитесь, что сервисный аккаунт (`client_email`) имеет права Editor над Google Sheet.

4. Установите зависимости и запустите проект:

```powershell
npm install
npm start
```

Для разработки с автоперезагрузкой:

```powershell
npm run dev
```

## Конфигурация и переменные окружения

| Переменная | Описание |
|------------|----------|
| `MAX_BOT_TOKEN` | Токен MAX-бота (обязательно) |
| `GOOGLE_SHEETS_ID` | ID Google Sheets таблицы |
| `GOOGLE_CLIENT_EMAIL` | Email сервисного аккаунта |
| `GOOGLE_PRIVATE_KEY` | Приватный ключ (одна строка с `\n`) |
| `GOOGLE_CALENDAR_ID` | ID календаря (опционально) |
| `DEFAULT_TIMEZONE` | Таймзона по умолчанию, если в `Настройки` нет `таймзона` |
| `MANAGER_CHAT_ID` | user_id менеджера в MAX для `/admin` и уведомлений |
| `BARBER_PHONE` | Телефон салона (fallback для напоминаний) |
| `BARBER_ADDRESS` | Адрес салона (fallback для напоминаний) |
| `WORKDAY_START_HOUR` | Начало рабочего дня по умолчанию (10) |
| `WORKDAY_END_HOUR` | Конец рабочего дня по умолчанию (20) |
| `ENABLE_WELCOME_REMINDER` | Приветственные напоминания (`true` / не задано = выкл.) |

> `MANAGER_CHAT_ID` — историческое имя переменной (миграция с другой платформы). В MAX это **user_id** пользователя, не chat id.

## Интеграция с Google Calendar (опционально)

- Переменная: `GOOGLE_CALENDAR_ID` — ID календаря (`your-calendar-id@group.calendar.google.com` или email владельца).
- Используются те же `GOOGLE_CLIENT_EMAIL` и `GOOGLE_PRIVATE_KEY`, что и для Sheets.
- Сервисному аккаунту нужно право «Вносить изменения в события» в настройках календаря.

Если календарь недоступен или переменная не задана — интеграция игнорируется, бот продолжает работать с Google Sheets.

## Структура Google Sheets

При старте вызывается `ensureSheetsStructure()` и создаются листы со стандартными заголовками.

### Лист `Настройки`

Ключ/значение. Основные ключи: `таймзона`, `телефон_мастера`, `адрес_мастера`, `напоминание_28день_текст`, `ссылка_на_чаевые`, `портфолио_фото` (JSON-массив HTTPS-URL), `ссылка_на_локацию`.

### Лист `Расписание`

Рабочие дни и часы: `Дата`, `День_недели`, `Время_начала`, `Время_окончания`, `Обед_начало`, `Обед_окончание`.

- Конкретная дата имеет приоритет над шаблоном по дню недели.
- Изменения применяются мгновенно — клиенты видят актуальное расписание без перезапуска бота.
- Используется «окно» из первых 50 строк: устаревшие даты автоматически вычищаются.

### Лист `Блокировка времени`

Блокировки слотов: `Дата`, `Время_начала`, `Время_окончания`, `Статус`, `Услуга`, `Примечание`. Для блокировки: `статус=заблокировано`.

### Лист `Записи`

Активные записи за последние 2 месяца. Колонки: `ID_записи`, `Создано_UTC`, `Услуга`, `Цена`, `Дата`, `Время_начала`, `Время_окончания`, `Имя_клиента`, `Телефон`, `Комментарий`, `Статус`, `Код_отмены`, `Max_ID`, `Исполнено_UTC`, `Отменено_UTC`.

Колонка `Цена` сохраняет стоимость на момент записи (важно для статистики доходов).

### Лист `Записи_Архив`

Те же колонки, что у `Записи`. История старше 2 месяцев. Заполняется автоматической ротацией.

### Лист `Клиенты`

`ID_клиента`, `Первое_посещение_UTC`, `Max_ID`, `Имя`, `Телефон`, `Последняя_запись_UTC`, `Всего_записей`, `BanStatus`, `BanReason`, `Напоминание_28день_UTC`, `Последняя_рассылка_UTC`.

**Услуги** хранятся в `services.json` в корне проекта. Управление — через админ-меню («Управление услугами»).

## Как это работает

```
index.js
  ├── initConfig (src/config)
  ├── createSheetsService (src/services/googleSheets.js)
  ├── createCalendarService (опционально)
  ├── Bot + MaxAdapter (src/adapters/maxAdapter.js)
  ├── middleware: maxSession, rateLimiter, callbackValidator, messageSizeLimiter
  ├── registerUserHandlers (src/maxBot/userHandlers.js)
  ├── registerBookingHandlers (src/maxBot/scenes/bookingScene.js)
  ├── registerAdminHandlers (src/maxBot/admin/)
  └── setupReminders (src/services/reminders.js)
```

- **Сессии**: `src/middleware/maxSession.js` хранит состояние в `sessions.json`. Запись — машина состояний `ctx.session.step` (не WizardScene).
- **Бизнес-логика**: `src/services/booking.js` — услуги, слоты, пересечения, создание записи.
- **Google Sheets**: `src/services/googleSheets.js` — CRUD, in-memory кэш (TTL ~30 мин для расписания дня), почасовая очистка устаревших записей кэша.
- **Оптимизация календаря**: при выборе даты проверяются только рабочие часы; слоты — при клике на конкретную дату.
- **Архивирование**: записи старше 2 месяцев переносятся в `Записи_Архив` (1-го числа в 03:00). Клиентские операции читают только активные записи.

## Ограничение записей

- **Лимит:** не более 3 активных записей на пользователя (на любые даты).
- **Идентификация:** по `Max_ID`, `chatId` или `phone`.
- При превышении бот блокирует создание и предлагает отменить существующие записи.

## Бан пользователей

- Бан через админ-меню по числовому **Max ID**. Синхронизация между `banned.json` и листом `Клиенты`.
- Забаненные: не могут записаться, исключаются из рассылок (`skipBanned`).

## Команды и UX

### Клиент

- `/start` — приветствие, портфолио (до 6 фото), главное меню.
- Inline-кнопки: «Записаться 💇‍♂️», «Мои записи», «Прайс», «Как добраться 🗺️».
- `/book` — запись; `/price` — прайс; `/cancel` — отмена текущего процесса записи.
- Запрос телефона: `Keyboard.button.requestContact`.

### Админ-режим

- `/admin` — только для `MANAGER_CHAT_ID` (user_id в MAX).
- Админ-меню — **inline callback-кнопки** под сообщением.
- `/admin_cancel` — отмена текущего пошагового действия.
- Выход: кнопка «Вернуться в пользовательский режим».

Главное меню: Просмотр записей, Статистика, Отмена по коду, Массовая рассылка, Финансовая статистика, Статус рассылки, Настройки.

Раздел «Настройки»: бан/разбан, услуги, напоминание 28 дней, чаевые, контакты, портфолио (HTTPS-URL), локация, расписание.

**Процесс записи:** услуга → дата (inline) → время (слоты 15 мин) → имя + контакт → комментарий → подтверждение.

**Календарь дат:** только текущий месяц; после 15-го — также следующий. Прошедшие дни скрыты. Только рабочие дни из `Расписание`.

## Напоминания и cron

| Задача | Расписание | Таймзона |
|--------|------------|----------|
| Напоминание за день до записи | 08:00 ежедневно | салон |
| Напоминание за 2 часа | каждые 15 мин (окно 105–135 мин до начала) | салон |
| Автозавершение записей (`исполнено`) | каждые 30 мин | салон |
| Напоминание 28 дней без визита | 11:00 ежедневно | салон |
| Очистка `sessions.json` | 02:00 ежедневно | салон |
| Сброс меток рассылки | понедельник 00:00 | салон |
| Сброс кэша 2-часовых напоминаний | 00:00 UTC ежедневно | UTC |
| Очистка кэша Google Sheets | каждый час | салон |
| Ротация записей в архив | 1-го числа в 03:00 | салон |

Между отправками в напоминаниях — троттлинг ~500 мс. Cron-задачи защищены от параллельного выполнения.

## Надёжность и обработка ошибок

- Глобальные обработчики `unhandledRejection` и `uncaughtException`.
- Ошибки MAX API (403, 429, 400) через `MaxError` — некритичные, процесс не завершается.
- `src/utils/safeMessaging.js` — безопасная отправка (`safeSendMessage`, `safeSendPhoto`, `safeReply`).

## Безопасность

1. **Админ-доступ** — только `MANAGER_CHAT_ID` (`ctx.user.user_id`).
2. **Rate limiting** — general 30/мин, admin 10/мин, сценарий записи 15/мин.
3. **Валидация** — Max ID, телефоны, имена, комментарии; санитизация XSS.
4. **Сессии** — лимит 10 KB, очистка неактивных (>30 дней), макс. 150 записей.
5. **Рассылки** — макс. 250/день, подтверждение, логирование в `logs/security.log`.
6. **Аудит зависимостей:** `npm run security:audit`, `npm run security:fix`, `npm run security:check`.

Файлы: `src/utils/security.js`, `src/middleware/rateLimiter.js`, `src/utils/logger.js`, `src/utils/backup.js`.

## Развёртывание

- Не коммитьте `.env`, `credentials.json`, `sessions.json`, `banned.json`, `logs/`.
- Для продакшена: pm2 или systemd.
- Регулярно проверяйте `logs/security.log` и запускайте `npm run security:check`.
