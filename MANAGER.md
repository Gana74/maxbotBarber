# Инструкция для менеджера

Этот файл — инструкция для менеджера салона и администратора сервера по работе с ботом в **мессенджере MAX**, Google Таблицами и Google Календарём.

## Навигация по документации

| Файл | Для кого |
|------|----------|
| [README.md](README.md) | Разработчики: архитектура, API, cron, безопасность |
| [MASTER.md](MASTER.md) | Мастер салона: пошаговая работа в боте и Google Sheets |
| [MANAGER.md](MANAGER.md) | Менеджер и админ сервера: настройка `.env`, Google API, справочник |

## Кому полезно

- Менеджеру, который просматривает записи, блокирует время и получает уведомления о новых и отменённых записях.
- Администратору сервера, который настраивает переменные окружения и запускает бота.

## О платформе

Бот работает в мессенджере **MAX**. Клиенты и менеджер общаются с ботом в личном чате MAX. Данные о записях, клиентах и настройках хранятся в Google Sheets; события могут синхронизироваться с Google Calendar.

> **Важно про таблицу:** идентификатор пользователя MAX (`user_id`) хранится в колонке `Max_ID` на листах `Клиенты`, `Записи` и `Записи_Архив`.

## Привязка к Google Таблицам и Google Календарю + скачивание credentials.json

Ниже описана настройка доступа бота к Google Sheets и Google Calendar через сервисный аккаунт Google. В результате вы получите файл `credentials.json` (для хранения локально) и заполните переменные в `.env`.

**Важное:**

- В рантайме проект использует переменные окружения `GOOGLE_CLIENT_EMAIL` и `GOOGLE_PRIVATE_KEY`, а не файл `credentials.json` напрямую. JSON можно хранить локально как источник данных для этих переменных.
- Никогда не коммитьте `credentials.json` и `.env` в публичный репозиторий.

### Шаг 1 — Создайте проект в Google Cloud Console

1. Откройте https://console.cloud.google.com (войдите под вашим Google‑аккаунтом).
2. В верхней панели нажмите Select project → New Project, задайте имя (например, Barber Bot) и создайте проект.

### Шаг 2 — Включите API

1. Откройте меню APIs & Services → Library.
2. Найдите и включите:
   - Google Sheets API
   - Google Calendar API

### Шаг 3 — Создайте сервисный аккаунт

1. Перейдите в IAM & Admin → Service Accounts → Create Service Account.
2. Задайте имя (например, barber-bot) и создайте.
3. Роль на шаге Assign roles можно пропустить либо выбрать Editor (необязательно для доступа к конкретным ресурсам, т.к. доступ будет дан через «Поделиться» в Sheets/Calendar).
4. После создания откройте созданный аккаунт → Keys → Add key → Create new key → JSON. Скачается файл `credentials.json`.

**Что важно из credentials.json:**

- `client_email` — адрес сервисного аккаунта вида `something@project-id.iam.gserviceaccount.com`
- `private_key` — приватный ключ (многострочный блок между BEGIN/END PRIVATE KEY)

### Шаг 4 — Поделитесь доступом к Google Sheet с сервисным аккаунтом

1. Откройте вашу таблицу Google Sheets, где будут храниться данные.
2. Нажмите Share и добавьте `client_email` из `credentials.json` как Editor (Редактор).
3. Сохраните.

**Как получить ID таблицы (`GOOGLE_SHEETS_ID`):**

- Откройте таблицу в браузере. В URL часть между `/d/` и `/edit` — это ID.
  Пример: `https://docs.google.com/spreadsheets/d/1AbCdEfGhIjKlMnOpqR/edit` → ID = `1AbCdEfGhIjKlMnOpqR`

### Шаг 5 — Дайте сервисному аккаунту доступ к календарю

1. Откройте Google Calendar (в браузере) под владельцем нужного календаря.
2. Слева выберите нужный календарь → «Настройки и доступ» → «Открыть доступ для конкретных пользователей» → «Добавить пользователей».
3. Впишите `client_email` и назначьте право «Вносить изменения в события» (Make changes to events).

**Как получить ID календаря (`GOOGLE_CALENDAR_ID`):**

- Для вторичных календарей ID отображается в настройках календаря (раздел «Интегрировать календарь»), обычно вида `your-calendar-id@group.calendar.google.com`.
- Для основного календаря аккаунта Google можно использовать email владельца (например, `your.name@gmail.com`).

### Шаг 6 — Токен MAX-бота

1. Зарегистрируйте и настройте бота на [платформе MAX для партнёров](https://business.max.ru).
2. После модерации получите токен: раздел **Чат-боты → Интеграция → Получить токен**.
3. Токен — секретный ключ доступа к боту. Не публикуйте его и не передавайте посторонним.

### Шаг 7 — Заполните `.env` в корне проекта

Создайте или откройте файл `.env` и заполните значения:

```
MAX_BOT_TOKEN=ваш_токен_бота_MAX
GOOGLE_SHEETS_ID=скопированный_id_таблицы
GOOGLE_CLIENT_EMAIL=client_email_из_credentials.json
GOOGLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
GOOGLE_CALENDAR_ID=идентификатор_календаря
DEFAULT_TIMEZONE=Asia/Yekaterinburg
MANAGER_CHAT_ID=1234567890
BARBER_PHONE=+7 999 123-45-67
BARBER_ADDRESS=ул. Примерная, д. 1
WORKDAY_START_HOUR=10
WORKDAY_END_HOUR=20
ENABLE_WELCOME_REMINDER=true
```

**Подсказки по `GOOGLE_PRIVATE_KEY`:**

- Ключ многострочный. В `.env` его нужно записать одной строкой, заменив переводы строк на символы `\n`.
- Код автоматически преобразует `\n` в реальные переводы строк при запуске.

**Опциональные переменные:**

- `GOOGLE_CALENDAR_ID` — без него календарная синхронизация отключена.
- `MANAGER_CHAT_ID` — без него уведомления менеджера и доступ к `/admin` не работают (см. ниже).
- `BARBER_PHONE`, `BARBER_ADDRESS` — используются в напоминаниях, если не заданы в Google Sheets.
- `ENABLE_WELCOME_REMINDER` — включает приветственные напоминания (`true` / не задано = выкл.).

### Шаг 8 — Проверка работы

1. Установите зависимости и запустите бота:
   ```bash
   npm install
   npm start
   ```
2. На первом запуске сервис создаст недостающие листы и заголовки в таблице. Если прав недостаточно, в логах будет ошибка «insufficient permissions» — проверьте, что вы расшарили таблицу сервисному аккаунту как Editor.
3. Для календаря: при создании новых записей должны появляться события в указанном календаре. Если нет — проверьте `GOOGLE_CALENDAR_ID` и доступ «Вносить изменения в события» для `client_email`.

### Устранение неполадок (настройка)

- **PERMISSION_DENIED** при обращении к таблице/календарю: проверьте, что именно `client_email` из `credentials.json` добавлен в доступы и роль — Editor (таблица) / Make changes to events (календарь).
- **invalid_grant / unauthorized_client:** убедитесь, что включены нужные API в Google Cloud (Sheets/Calendar) и что время на сервере синхронизировано (NTP).
- **malformed private key:** проверьте кавычки и экранирование `\n` в `GOOGLE_PRIVATE_KEY` в `.env`.
- События не создаются, но записи в таблице есть: проверьте наличие `GOOGLE_CALENDAR_ID`. Без него календарная интеграция отключена, это не ошибка.
- Бот не отвечает в MAX: проверьте `MAX_BOT_TOKEN`, что бот прошёл модерацию и процесс на сервере запущен.

### Примечание о credentials.json

- Файл можно хранить только локально для справки. В репозиторий не добавлять. Для продакшена используйте исключительно переменные окружения.

## Включение менеджерских уведомлений

1. В `.env` (или в переменных окружения на сервере) задайте `MANAGER_CHAT_ID` равным вашему **user_id в MAX**.
2. Если `MANAGER_CHAT_ID` не задан, уведомления менеджера не отправляются, и команда `/admin` недоступна никому.

**Как получить свой user_id в MAX:**

- Напишите боту любое сообщение и попросите разработчика посмотреть лог сервера — в отладочных сообщениях отображается `user_id`.
- Либо разработчик может временно залогировать `ctx.user.user_id` при вашем обращении к боту.

> `MANAGER_CHAT_ID` — в MAX это **не** chat id, а именно **user_id** пользователя.

После установки `MANAGER_CHAT_ID` и перезапуска бота вы будете получать в MAX уведомления о новых записях и об отменах.

## Просмотр записей

- **В боте:** кнопка `Просмотр записей` в админ-меню. Бот покажет активные записи с кодами отмены (первые 50 записей).
- **В Google Sheets:** откройте таблицу, указанную в `GOOGLE_SHEETS_ID`.
- Лист `Записи` содержит активные записи за последние 2 месяца. Отфильтруйте по столбцу `Статус` = `активна` и дате.
- Лист `Записи_Архив` содержит исторические записи старше 2 месяцев (для полной истории используйте оба листа).
- Полезные столбцы: `ID_записи`, `Услуга`, `Цена`, `Дата`, `Время_начала`, `Время_окончания`, `Имя_клиента`, `Телефон`, `Комментарий`, `Код_отмены`, `Max_ID` (ID пользователя MAX).

**Оптимизация производительности:**

- Система автоматически разделяет записи на активные (последние 2 месяца) и архивные (старше 2 месяцев).
- Это обеспечивает быструю работу бота при выборе времени клиентами (<1 секунда вместо 2–5 секунд).
- Для админ-статистики и отчётов система автоматически объединяет данные из обоих листов.

## Бан пользователей

- Для бана: **«⚙️ Настройки»** → **«Забанить пользователя»**. В таблице на листе `Клиенты` будет установлен `BanStatus = banned`, а в `BanReason` — причина (если указали).
- Разбан: **«⚙️ Настройки»** → **«Разбанить пользователя»** снимет бан в таблице (`BanStatus` очистится) и из локального списка `banned.json`.
- Забанированные пользователи:
  - не могут начать запись (бот сообщит о блокировке);
  - не могут создать запись (сервис бронирования вернёт ошибку `reason: banned`);
  - исключаются из рассылок при включённой опции `skipBanned`.

При бане и разбане введите **числовой Max ID** пользователя в MAX (колонка `Max_ID` на листе `Клиенты`).

## Работа в боте — админ‑режим

### Как войти

1. Откройте диалог с ботом в **MAX**.
2. Отправьте команду `/admin`. Команда активна только для аккаунта, чей `user_id` совпадает с `MANAGER_CHAT_ID`.
3. Бот ответит: «Включён режим администратора. Выберите действие:» и покажет **inline-кнопки** под сообщением.

> Админ-меню реализовано через **inline-кнопки** (под текстом сообщения).

### Главное админ-меню

| Кнопка | Действие |
|--------|----------|
| Просмотр записей | Показать активные записи (до 50) с кодами отмены |
| Статистика | Количество активных записей и клиентов в базе |
| Отмена по коду | Ввести 6-символьный код отмены записи |
| Массовая рассылка | Текстовая или фото-рассылка клиентам |
| 📊 Финансовая статистика | Доходы по периодам |
| 📊 Статус рассылки | Сколько клиентов доступно для рассылки сегодня |
| ⚙️ Настройки | Дополнительные функции |
| Вернуться в пользовательский режим | Выход из админ-режима |

### Раздел «⚙️ Настройки»

| Кнопка | Действие |
|--------|----------|
| Забанить пользователя | Ввод числового Max ID пользователя в MAX |
| Разбанить пользователя | Ввод числового Max ID |
| Управление услугами | Добавление, редактирование, удаление услуг |
| Редактировать напоминание 28 дней | Текст напоминания неактивным клиентам |
| Редактировать ссылку на чаевые | Ссылка или номер для чаевых |
| Изменить контакты | Телефон и адрес салона |
| Загрузить фото в портфолио | Добавить HTTPS-ссылку на фото |
| Удалить фото | Удалить фото по номеру из списка |
| Сохранить локацию | Ссылка на Яндекс.Карты / маршрут |
| Настройки расписания | Управление рабочими днями и часами |
| Назад в админ-меню | Возврат в главное меню |

### Команды администратора

| Команда | Описание |
|---------|----------|
| `/admin` | Включить режим администратора |
| `/admin_cancel` | Отменить текущее пошаговое действие и вернуться в главное админ-меню |

**Выход из админ-режима:** нажмите кнопку **«Вернуться в пользовательский режим»**. Команда `/user` в текущей версии бота не используется.

**Пошаговые действия:** после выбора пункта меню (отмена по коду, рассылка, бан, расписание и т.д.) бот ожидает ваш ввод текста или изображения. Отмена — `/admin_cancel`.

**Пример главного меню:**

```
Вы: /admin

Бот: Включён режим администратора. Выберите действие:

[Просмотр записей] [Статистика]
[Отмена по коду]
[Массовая рассылка]
[📊 Финансовая статистика] [📊 Статус рассылки]
[⚙️ Настройки]
[Вернуться в пользовательский режим]
```

### Портфолио и премиальная визитка

После команды клиента `/start` бот показывает до 6 лучших работ из портфолио (источник: `Настройки.портфолио_фото`).

**Как обновить:**

- **«⚙️ Настройки»** → **«Загрузить фото в портфолио»** — отправьте **прямую HTTPS-ссылку** на изображение (например, с хостинга или облака). Файл как вложение не принимается — бот попросит ссылку.
- Ссылка сохраняется в таблице как элемент JSON-массива (до 50 фото в хранилище).
- **«⚙️ Настройки»** → **«Удалить фото»** — бот покажет превью (до 6 последних), вы введите номер для удаления.

### Как добраться (карта)

Кнопка «Как добраться» доступна в главном меню клиента и открывает ссылку на карту (источник: `Настройки.ссылка_на_локацию`).

**Как обновить:**

- **«⚙️ Настройки»** → **«Сохранить локацию»** — перезапишите ссылку (`http://` или `https://`).

### Управление расписанием через бота

Менеджер может управлять рабочими днями и часами мастера не только через Google Sheets, но и напрямую в боте.

**Как открыть:**

1. `/admin` → включить админ‑режим.
2. Нажать **«⚙️ Настройки»**.
3. Нажать **«Настройки расписания»**.

**Подменю:**

```
[Просмотр расписания на дату]
[Изменить/добавить расписание на дату]
[Удалить расписание на дату]
[Посмотреть всё расписание]
[Шаблоны по дням недели]
[Назад в админ-меню]
```

**Кратко по функциям:**

- **Просмотр расписания на дату** — введите дату (`ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`), бот покажет рабочее время и обед (если заданы) или сообщит, что это выходной.
- **Изменить/добавить расписание на дату** — пошаговый диалог: дата → начало рабочего дня → конец → обед (время или `-` для отсутствия) → подтверждение **«Да»** / **«Нет»**. Данные сохраняются в лист `Расписание`, изменения сразу видны клиентам.
- **Удалить расписание на дату** — после ввода даты бот удаляет расписание для неё, день становится выходным.
- **Посмотреть всё расписание** — бот выводит текущее окно расписания (первые 50 строк листа `Расписание`): отдельные даты + шаблоны по дням недели.
- **Шаблоны по дням недели** — просмотр и редактирование стандартных часов по дням (`Пн`, `Вт`, `mon` и т.п.); удаление командой вида `удалить Пн`.

> Внутри кода используется «скользящее окно» строк листа `Расписание`: устаревшие прошедшие даты автоматически очищаются, чтобы таблица не разрасталась.

## Финансовая статистика

Функция позволяет отслеживать доходы мастера по различным периодам и анализировать эффективность услуг.

### Как использовать

1. В админ‑режиме нажмите **«📊 Финансовая статистика»**.
2. Бот покажет inline-кнопки с периодами:
   - **Сегодня** — доходы за текущий день
   - **Вчера** — доходы за вчерашний день
   - **Эта неделя** — с понедельника текущей недели по сегодня
   - **Прошлая неделя** — понедельник — воскресенье прошлой недели
   - **Этот месяц** — с 1‑го числа текущего месяца по сегодня
   - **Прошлый месяц** — весь прошлый месяц
   - **По услугам** — статистика по всем услугам за всё время
3. Выберите период кнопкой.
4. Бот покажет статистику доходов.

### Что показывает статистика

**Пример вывода:**

```
📈 Выручка за 10 января 2026:
• Всего: 12 500 ₽
• Средний чек: 1 562,5 ₽
• Записей исполнено: 8
• Новых клиентов: 3
• Записей отменено: 2

Топ услуг:
• Мужская стрижка — 6 000 ₽ (4 записи)
• Оформление бороды — 4 500 ₽ (3 записи)
• Женская стрижка — 2 000 ₽ (1 запись)
```

**Информация в статистике:**

- **Всего** — общая сумма доходов за выбранный период
- **Средний чек** — средняя сумма с завершённой записи
- **Записей исполнено** — записи со статусом `исполнено`
- **Новых клиентов** — впервые посетившие салон в период (по `Первое_посещение_UTC` в листе `Клиенты`)
- **Записей отменено** — отмены в период (по `Отменено_UTC`)
- **Топ услуг** — услуги, отсортированные по сумме доходов

### Важные особенности

- Учитываются только завершённые записи (статус `исполнено`).
- Цена сохраняется при создании записи — отражает стоимость на момент записи.
- Фильтрация по дате исполнения: поле `Исполнено_UTC` (приоритет) или дата записи.
- Записи с пустой или нулевой ценой не учитываются в доходах, но учитываются в количестве.

### Периоды

- **Сегодня/Вчера** — от начала до конца дня по таймзоне салона
- **Неделя** — с понедельника по воскресенье (или по сегодня для текущей недели)
- **Месяц** — с 1‑го числа по последний день месяца (или по сегодня для текущего)
- **По услугам** — все завершённые записи без ограничения по дате

В листе `Записи` колонка **`Цена`** (после `Услуга`) заполняется автоматически при создании записи. Для старых записей колонка может быть пустой — такие записи не учитываются в расчёте доходов.

## Массовая рассылка (текст и картинки)

### Возможности

- Текстовая рассылка.
- Рассылка одного изображения с подписью (отправьте фото как вложение в MAX; подпись — текст к изображению).
- Фильтрация по бан-листу.
- Исключение клиентов, которым уже отправляли менее 24 часов назад.
- Предпросмотр и подтверждение перед отправкой.
- Автоматическое разбиение на несколько дней при более 250 получателях.
- Троттлинг 750 мс между сообщениями (снижение риска лимитов MAX API).

### Как отправить текстовую рассылку

1. `/admin` → **«Массовая рассылка»**.
2. Отправьте текст одним сообщением (до 4000 символов после санитизации).
3. Бот покажет предпросмотр: количество получателей и предупреждения о лимитах.
4. Нажмите **«Подтвердить рассылку ✅»** или **«Отменить ❌»**.
5. После завершения: «Рассылка завершена. Отправлено: X. Ошибок: Y.»

### Как отправить рассылку с картинкой

1. `/admin` → **«Массовая рассылка»**.
2. Отправьте **изображение** как вложение. Подпись к фото (caption) станет текстом рассылки.
3. Бот покажет предпросмотр (отдельно отправит фото менеджеру) и предложит подтвердить.
4. Подтвердите или отмените.

**Важно:**

- Поддерживаются форматы JPEG, PNG, WebP; размер до 10 МБ.
- Отправляется одно фото на сообщение (альбомы не поддерживаются).
- Для доставки клиентам используется токен вложения MAX или URL изображения.

### Ограничения и примечания

- **Максимум 250 получателей в день** — система ограничивает количество за одну рассылку.
- Получатели — клиенты из листа `Клиенты` с заполненным `Max_ID`, за вычетом бан-листа и недавно отправленных (<24 ч).
- Метка `Последняя_рассылка_UTC` в `Клиенты` обновляется после успешной отправки.
- Если клиентов больше 250, остальные получат рассылку на следующий день (когда метки станут старше 24 часов).
- Метки рассылки сбрасываются каждую неделю по понедельникам в 00:00 по таймзоне салона.
- Кнопка **«📊 Статус рассылки»** показывает: доступно сегодня, ожидающие, всего клиентов, дату следующего сброса меток.

### Типичные сценарии

- Срочная промо-акция: картинка с акцией и подписью.
- Изменения расписания или цен: текст без фото.

### Что проверить, если «не отправляется»

- Вы в админ-режиме (`/admin`) и ваш `user_id` совпадает с `MANAGER_CHAT_ID`.
- У клиентов заполнен `Max_ID` в таблице и они не забанены.
- Посмотрите ответ бота после рассылки — количество ошибок.
- При лимитах MAX API увеличьте задержку (`throttleMs`) в коде при вызове `broadcastToClients`.

## Безопасность и ограничения

### Ограничения массовых рассылок

- Максимум **250 получателей в день**
- Метки в `Клиенты.Последняя_рассылка_UTC`
- Исключение отправленных за последние 24 часа
- Сброс меток по понедельникам в 00:00 (таймзона салона)
- Троттлинг ~750 мс между сообщениями
- Обязательное подтверждение перед отправкой
- Логирование в `logs/security.log`

### Rate Limiting

Бот защищён от злоупотребления:

| Тип запросов | Лимит |
|--------------|-------|
| Админ-команды и inline-кнопки админки | 10 в минуту |
| Обычные сообщения пользователя | 30 в минуту |
| Сценарий записи (пошаговый диалог) | 15 в минуту |

При превышении: «Слишком много запросов. Пожалуйста, подождите немного.»

### Локальные данные и логирование

**Локальные файлы** (рекомендуется периодически копировать вручную):

- `sessions.json` — сессии пользователей
- `banned.json` — локальный бан-лист
- `services.json` — каталог услуг

Папка `backups/` указана в `.gitignore` для хранения резервных копий.

**Логи:** критичные действия администратора записываются в `logs/security.log`:

- Включение/выключение админ-режима
- Бан/разбан
- Отмена записей администратором
- Массовые рассылки
- Управление услугами
- Редактирование напоминания 28 дней, ссылки на чаевые, контактов

## Отмена записи вручную

### Через бота (рекомендуется)

1. **«Просмотр записей»** — найдите запись и код отмены.
2. **«Отмена по коду»** — введите код (например: `A3K9X2`).
3. Бот отменит запись и уведомит клиента в MAX (если в записи есть `Max_ID`).

### Через Google Sheets

1. В `Записи` найдите строку.
2. В `Статус` установите `отменена`.
3. В `Отменено_UTC` впишите текущее время в ISO (например: `2025-12-23T10:30:00Z`).
4. При необходимости сообщите клиенту вручную; автоматическое уведомление при ручной правке в таблице не отправляется.

> Корректная отмена нужна, чтобы система не предлагала занятые слоты и отчёты были точными. Код отмены — в колонке `Код_отмены` или в уведомлении менеджеру при создании записи.

| Статус | Значение |
|--------|----------|
| `активна` | Запись активна, клиент ожидает услугу |
| `отменена` | Отменена клиентом или администратором |
| `исполнено` | Услуга оказана, запись автоматически завершена |
| `заблокировано` | Время заблокировано для записи (лист `Блокировка времени`) |

## Автоматическое завершение записей

Система обновляет статус на `исполнено` сразу после окончания времени услуги. Проверка — **каждые 30 минут**.

**Уведомление клиенту в MAX:**

После завершения клиент получает сообщение с благодарностью и ссылкой на чаевые (если настроена). Формат: «{название услуги} завершена, благодарю что выбираете меня!» + блок о чаевых.

Ссылку на чаевые: **«⚙️ Настройки»** → **«Редактировать ссылку на чаевые»**. Допустимы `http://`, `https://`, `t.me/` или номер телефона.

## Автоматическая ротация записей в архив

| Параметр | Значение |
|----------|----------|
| Когда | 1-го числа каждого месяца в 03:00 по таймзоне салона |
| Что | Записи старше 2 месяцев переносятся из `Записи` в `Записи_Архив` |

**Зачем:**

- Быстрая работа календаря записи (<1 с)
- Меньше нагрузка на память
- Полная история сохраняется в архиве

**Важно:**

- Ротация автоматическая
- Статистика и отчёты используют оба листа
- При первом запуске после обновления старые записи могут мигрировать в архив

Колонка **`Исполнено_UTC`** в `Записи` — дата и время отметки об исполнении (ISO UTC).

## Блокировка слотов (закрыть время для записи)

Через лист **`Блокировка времени`**.

**Формат строки:** `Дата | Время_начала | Время_окончания | Статус | Услуга | Примечание`

| Колонка | Описание |
|---------|----------|
| `Дата` | `YYYY-MM-DD` |
| `Время_начала` / `Время_окончания` | `HH:MM` (24 ч, с ведущими нулями) |
| `Статус` | Строго `заблокировано` |
| `Услуга` | Опционально (`ВСЕ`, `ВЫХОД` и т.п.) |
| `Примечание` | Пояснение для менеджеров |

**Примеры:**

- Обед 24.12 с 13:00 до 14:00: `2025-12-24 | 13:00 | 14:00 | заблокировано | | перерыв на обед`
- Весь день: `2025-12-31 | 00:00 | 23:59 | заблокировано | | закрыто на Новый год`

**Отмена блокировки:** удалите строку или измените `Статус` на значение, отличное от `заблокировано`.

**Нюансы:**

- Время в таймзоне салона (`Настройки.таймзона` или `DEFAULT_TIMEZONE`).
- Изменения учитываются **мгновенно** при расчёте слотов.
- Блокировка не отменяет уже подтверждённые записи автоматически.

## Таймзона салона

- Хранится в `Настройки.таймзона`. Если пусто — `DEFAULT_TIMEZONE` из `.env`.
- Примеры: `Europe/Moscow`, `Asia/Yekaterinburg`.
- Влияет на напоминания, отображение дат и сброс меток рассылки.

## Рабочие часы (лист `Расписание`)

Задаёт часы работы по дням недели и/или исключения по датам. Определяет, какие дни видны в календаре записи.

**Колонки:**

| Колонка | Описание |
|---------|----------|
| `Дата` | Конкретная дата `YYYY-MM-DD` (приоритет над днём недели) |
| `День_недели` | `понедельник`, `пн`, `mon` и т.п. |
| `Время_начала` / `Время_окончания` | `HH:MM` |
| `Обед_начало` / `Обед_окончание` | Опционально |

**Приоритеты:**

1. Запись по конкретной `Дата`
2. Иначе — по `День_недели`
3. Иначе — выходной (день скрыт в календаре)

**Примеры (со строки 2):**

- Понедельники: ` | понедельник | 10:00 | 20:00`
- Короткая форма: ` | пн | 10:00 | 20:00`
- Исключение на дату: `2025-05-01 |  | 12:00 | 16:00`
- С обедом: ` | пн | 10:00 | 20:00 | 13:00 | 14:00`

**Особенности:**

- Изменения видны клиентам **сразу** без перезапуска бота.
- В календаре только рабочие дни.
- Некорректное время игнорируется — день может считаться выходным.
- Если слоты заняты, дата всё равно видна; при выборе клиент увидит отсутствие свободного времени.

## Напоминание для неактивных клиентов (28 дней)

### Как работает

- Проверка **ежедневно в 11:00** по таймзоне салона.
- Клиенты, у которых `Последняя_запись_UTC` старше 28 дней, нет активных записей, заполнен `Max_ID`, не забанены и пусто `Напоминание_28день_UTC`.
- `Последняя_запись_UTC` обновляется при завершении записи (`исполнено`).
- Текст — из `Настройки.напоминание_28день_текст`; плейсхолдер `{clientName}`.
- Напоминание отправляется **один раз**; после успешной отправки заполняется `Напоминание_28день_UTC`.
- При новой записи клиента поле `Напоминание_28день_UTC` очищается.

### Редактирование текста

**«⚙️ Настройки»** → **«Редактировать напоминание 28 дней»** → отправьте новый текст.

Результат рассылки пишется в **лог сервера** (количество успешных отправок и ошибок).
